# ЛР-1 — Класс и инкапсуляция

## 1. Цель работы
Освоить объявление класса, инкапсуляцию (закрытые поля `_имя`), свойства `@property`
с сеттером и валидацией, магические методы `__str__`, `__repr__`, `__eq__`, разницу
между атрибутами класса и экземпляра, а также логическое состояние объекта.

## 2. Ход рассуждений: как появился класс `Car`

Предметная область — **Транспорт** (вариант 5), сущность — `Car`.

### Вопрос 1. Что является сущностью?
Конкретный физический автомобиль, стоящий на учёте под своим гос. номером.
Не «модель Toyota Camry» как товарная позиция (у модели нет пробега и топлива),
и не автопарк (он появится в ЛР-2 как отдельный класс-контейнер).

### Вопрос 2. Какие у него атрибуты?
| Атрибут | Тип | Меняется? | Что это |
|---|---|---|---|
| `_plate` | str | нет | гос. номер — идентификатор |
| `_brand`, `_model` | str | нет | марка и модель |
| `_year` | int | нет | год выпуска |
| `_mileage` | int | только растёт | пробег |
| `_tank_capacity` | float | нет | объём бака |
| `_fuel_level` | float | через методы | остаток топлива |
| `_status` | str | через методы | в гараже / в поездке / в ремонте |

Атрибуты класса (общие для всех машин): `MIN_YEAR`, `MAX_YEAR`, `FUEL_CONSUMPTION`,
`CATEGORY`, константы статусов, счётчик `total_created`.

«Возраст», «процент бака», «запас хода» — не хранятся, а вычисляются (`@property`),
иначе их пришлось бы синхронизировать с пробегом и топливом.

### Вопрос 3. Какие инварианты?
- номер — непустая строка 6–9 символов (нормализуется: верхний регистр, без пробелов);
- марка и модель — непустые строки;
- `MIN_YEAR ≤ год ≤ MAX_YEAR`, год — `int` (но не `bool`!);
- пробег ≥ 0 и никогда не уменьшается;
- `0 < объём бака ≤ 500`;
- `0 ≤ топливо ≤ объём бака`;
- ехать можно только в статусе «в поездке» и только если хватает топлива.

Все проверки вынесены в `validate.py` и написаны один раз: конструктор и сеттер
вызывают одну и ту же функцию.

### Вопрос 4. Что значит «равенство»?
Две машины равны, если совпадает **гос. номер**. Пробег, топливо и статус не участвуют:
та же машина после поездки остаётся той же машиной. Раз определён `__eq__`, определён
и `__hash__` (по номеру), чтобы объекты можно было класть в `set` и словари.

### Вопрос 5. Есть ли состояние?
Да, три статуса и четыре перехода:

```
   в гараже  --start_trip()-->  в поездке  --finish_trip()-->  в гараже
   в гараже  --send_to_service()-->  в ремонте  --finish_service()-->  в гараже
```

Методы перехода только меняют `_status` («ворота»). Бизнес-методы `drive()` и
`refuel()` меняют данные и проходят через эти ворота: `drive` работает только
в поездке, `refuel` запрещён в ремонте, `start_trip` невозможен с пустым баком.

## 3. Структура
- `validate.py` — функции `_ensure_*` (тип) и `_validate_*` (тип + диапазон);
- `model.py` — класс `Car`;
- `demo.py` — пять сценариев.

## 4. Демонстрация работы (`python demo.py`)
1. Создание, `print`, `repr`, атрибуты класса через класс и через экземпляр, счётчик.
2. Сравнение: `==` по номеру, `is`, сравнение с чужим типом, `set`.
3. Валидация конструктора: восемь некорректных вариантов через `try/except`.
4. Сеттер пробега (нельзя уменьшить, нельзя строку) и свойство без сеттера.
5. Состояния: запреты по статусу, поездка, нехватка топлива, заправка, ремонт, пустой бак.
