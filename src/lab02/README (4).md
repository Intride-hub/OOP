# ЛР-2 — Коллекция объектов

## 1. Цель работы
Понять разницу между моделью сущности (`Car`) и контейнером объектов (`Fleet`),
реализовать собственный контейнерный класс с добавлением, удалением, поиском,
итерацией, индексацией, сортировкой и логическими выборками.

## 2. Описание коллекции `Fleet` (автопарк)
Хранит список `_items` уникальных по гос. номеру машин.

| Задание | Что реализовано |
|---|---|
| на 3 | `add()` (только `Car`, без дубликатов), `remove()`, `get_all()` (копия списка) |
| на 4 | `find_by_plate()`, `find_by_brand()`, `__len__`, `__iter__`, `__contains__`, запрет дубликатов через `Car.__eq__` |
| на 5 | `__getitem__` (индексы и срезы), `remove_at()`, `sort(key, reverse)`, `sort_by_year()`, `sort_by_mileage()`, выборки `get_available()`, `get_in_service()`, `get_low_fuel()` — каждая возвращает **новый** `Fleet` |

Ключевое решение: `get_all()` и `__iter__` отдают копию, чтобы нельзя было
изменить содержимое парка в обход `add()`. Проверка дубликатов — это `car in self._items`,
которое вызывает `Car.__eq__` (сравнение по номеру).

## 3. Демонстрация работы (`python demo.py`)
1. Добавление пяти машин, вывод, удаление, повторный вывод.
2. Проверки: не-`Car`, дубликат (другой объект, тот же номер), удаление отсутствующей.
3. Поиск, `len()`, `for`, `in`.
4. Индексация `fleet[0]`, `fleet[-1]`, срез, `remove_at()`.
5. Сортировка тремя способами.
6. Выборки возвращают новый `Fleet`, исходный не меняется.
