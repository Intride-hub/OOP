# ЛР-4 — Интерфейсы и абстрактные классы (ABC)

## 1. Цель работы
Ввести контракты поведения через `abc.ABC` и `@abstractmethod`, использовать интерфейс
как тип, реализовать несколько интерфейсов в одном классе, фильтровать коллекцию по интерфейсу.

## 2. Описание интерфейсов (`interfaces.py`)
| Интерфейс | Обязательные методы | Смысл |
|---|---|---|
| `Printable` | `display() -> str` | умеет показать себя |
| `Comparable` | `compare_to(other) -> int` (+ готовые `is_greater_than`, `is_less_than`) | умеет сравнивать себя |
| `Earnable` | `earn(distance) -> float`, свойство `earnings` | приносит деньги |

## 3. Реализация в классах (`models.py`)
```
Car(Printable, Comparable)
 ├── Taxi(Car, Earnable)
 └── Truck(Car, Earnable)
```
- `display()` реализован по-разному в `Car`, `Taxi`, `Truck`.
- `compare_to()` реализован в `Car` (по пробегу) и **намеренно** не переопределён —
  критерий сравнения должен быть один на всю иерархию, иначе сортировка смешанного списка
  станет противоречивой.
- `earn()`: у `Taxi` — выполнить заказ (`complete_ride`), у `Truck` — рейс с грузом (`deliver`).
  Обычный `Car` `Earnable` не реализует — личная машина денег не приносит.

`services.py` — универсальные функции, которые знают только про интерфейсы:
`print_all(list[Printable])`, `find_max(list[Comparable])`, `total_earnings`, `work_day`.

`collection.py` — `get_by_interface()`, `get_printable()`, `get_comparable()`, `get_earnable()`,
`sort_comparable()` (через `functools.cmp_to_key`), `display_all()`, `total_earnings()`.

## 4. Демонстрация работы (`python demo.py`)
1. Интерфейс нельзя инстанцировать; класс без реализации метода — тоже; класс `Bicycle`,
   не связанный с машинами, выполняет `Printable`.
2. `print_all()` через интерфейс, `isinstance` по интерфейсу, `__mro__`, `work_day()`.
3. `Comparable`: `compare_to`, готовые методы интерфейса, `find_max()`.
4. Коллекция: фильтрация по интерфейсу, сортировка через `Comparable`, вывод через `Printable`.
